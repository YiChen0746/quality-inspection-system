## 二、验证记录（本地实测，非估算）

**后端接口**（`POST /api/score_contract`，真实模型调用）

| 用例 | 输入 | 结果 |
|---|---|---|
| 短合同 | 房屋租赁合同，379 字 | `score=60 level=中 evidence=4`，风险点带 `（依据：L2/L1/L3）`；`meta.truncated=false` |
| 长合同 | 技术服务合同，70,852 字 | `chunks=8 evaluated=4 truncated=true coveredChars=39808`，结论首条为“仅评估前 4 段…”覆盖提示；耗时 46s |
| 服务类分类 | 上述合同 | 命中条目含 `cat=服务/委托合同` 拆分后的分类，证明全等误杀已修 |
| 请求体超大 | 200KB 请求体 | 修复前 `500 request entity too large`；修复后正常解析（25MB 上限） |

**前端**：`npm run build-only`（vite build）通过，31.57s，产物含 `ContractDraft-*.js 44.13kB`、`IntelligentQA-*.js 1002kB`，只有既有的 chunk 体积警告。

**未通过项（既有问题，与本次改动无关）**：`npm run build`（含 `vue-tsc --build --force`）会在 `src/views/upload.vue`、`editword.vue`、`1.vue` 等文件上报 `TS6504: ... is a JavaScript file`。原因是这些 SFC 的 `<script>` 没有 `lang="ts"`，而 `tsconfig.app.json` 的 `include: ["src/**/*"]` 把 `.vue` 当 JS 纳入。用改动前的原始文件同样报同样错误，属仓库既有状态。

## 三、已知遗留（建议下一轮处理，本次未动）

1. 模型仍会给出方向相反的建议，例如合同已写明“不选择仲裁”，却建议“未约定仲裁条款”。属提示词与模型能力边界，需补一条“不得与原文明确约定相反”的约束。
2. 多个分段的 `risks` 存在同义重复（“验收标准不明确”与“验收标准不明确可能导致争议”），目前只做字面去重。
3. `IntelligentQA.vue` 产物体积 1MB，建议后续把技能中心拆成异步组件。
