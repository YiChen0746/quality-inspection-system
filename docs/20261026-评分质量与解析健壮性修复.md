# 风险评分质量与解析健壮性修复（2026-10-26 第二批）

上一批已把评分从「只评前 6000 字 + 失败静默返回 50 分」改为「全文分段 + 知识库溯源 + 明确报错」。本批处理实测中暴露的另外几类问题：**建议与原文明确约定相反**、**同义风险重复**、**模型输出 JSON 不可解析导致整段结论丢失**。

## 一、改动清单

| # | 问题 | 处理方式 |
|---|---|---|
| 1 | 原文已明确约定争议解决，模型仍建议「补充仲裁条款」；原文已定金额比例，仍当作缺失项 | 提示词新增规则 5：引用须保留原措辞，禁止把已约定事项说成「缺失/未约定」，只能就合理性提意见 |
| 2 | 同一实质问题被拆成多条、换措辞重复 | 提示词新增规则 6 + 解析后按二元组相似度归并（含「约定/条款」「时间/期限」等同义词归一） |
| 3 | 建议泛泛而谈「建议完善」，无法直接落地 | 提示词新增规则 7：建议须与风险逐条对应，尽量给出可直接替换/补充的条款文本 |
| 4 | 原文约定诉讼，模型建议改为仲裁；反之亦然 | 提示词新增规则 8；并新增确定性兜底 `detectExcludedPath` + `dropPathConflictItems`：原文写明「不选择仲裁/排除诉讼」时，直接滤掉推荐该方式的条目（指向条款冲突的条目保留） |
| 5 | 模型输出夹带中文引号、尾随逗号、代码围栏或半截 JSON，导致解析失败 → 接口 502 | 新增 `parseScoreJson`（四种修复尝试）+ `salvageScorePayload`（正则兜底取 score 与两个数组）+ 解析失败自动重试一次（追加「只输出 JSON」约束） |
| 6 | 模型把条目写成对象（`{"risk":"…","依据":"L1"}`），前端显示 `[object Object]` | 新增 `itemToText`：识别 risk/desc/text/title/依据 等字段，拼接为「…（依据：Lx）」 |
| 7 | 排查时看不到归并/过滤是否生效 | 评分返回的 `meta` 增加 `rawRiskCount`、`mergedRiskCount`、`excludedPaths`、`filteredByPath` |

## 二、实测证据

**用例一（333 字，含「双方一致确认，本合同不选择仲裁方式解决争议」）**

- 耗时 14.3s，`score=60 / 中`，`excludedPaths=["仲裁"]`
- 风险点 5 条，全部指向真实缺口：支付节点未绑定验收、违约金比例过低、保密期限过长、**争议解决仅约定诉讼但未明确管辖法院层级或地点**、未约定知识产权归属
- 检查「未约定争议解决 / 未约定仲裁 / 缺少仲裁条款」类矛盾表述：**0 条**
- 建议 5 条均带可直接替换的条款文本（如「任何一方违约，应支付合同总价 10% 的违约金」）

**用例二（11,642 字，强制切成 2 段）**

- 耗时 20.8s，`chunks=2, evaluated=2, truncated=false`
- `rawRiskCount=9 → mergedRiskCount=8`，近似归并生效
- 输出中不再出现 `[object Object]`

**离线单测（纯函数，抽取真实源码执行）**

- 相似归并 4 项、路径排除识别 3 项、路径冲突过滤 3 项：**10/10 通过**
- JSON 容错解析 5 种畸形输入（正常/中文引号/尾随逗号/代码围栏/半截 JSON）：**5/5 通过**

## 三、已知限制

1. 语义相同但用词差异较大的条目（如「未明确约定服务费用及支付节点」与「费用支付节点未明确」）仍可能并存，目前靠提示词规则 6 约束；未引入「再调一次模型做去重」，是为了不额外增加一次调用成本。
2. 路径冲突兜底按关键词判断，属于保守过滤：仅当原文出现「不选择/排除/不提交 + 仲裁或诉讼」时才触发，避免误伤正常条款。
3. `meta` 中的诊断字段仅供前端/排查使用，不参与展示口径。

## 四、回滚方式
