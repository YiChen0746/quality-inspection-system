# 合同质检系统 —— 云服务器部署文档

> 适用：Ubuntu 22.04 / Debian 11+，先用公网 IP 访问。照着本文从上往下执行即可。

---

## 〇、先买一台服务器

| 项目 | 建议 |
|---|---|
| 厂商 | 阿里云 / 腾讯云 / 华为云的**轻量应用服务器**即可（比 ECS/CVM 便宜且够用） |
| 系统 | **Ubuntu 22.04 LTS** |
| 配置 | **2 核 4G 内存**、40G 云盘、3M 以上带宽（前端打包后有 5MB 左右、内存要跑 Node + MySQL） |
| 价格 | 轻量服务器新用户通常一年几十到两百元区间，按厂商活动浮动 |
| 备案 | **用 IP 访问不需要备案**。以后想把域名指向国内服务器的 80/443，才需要 ICP 备案 |

购买后你会拿到：**公网 IP**、**root 密码或 SSH 密钥**。

> 安全组/防火墙只需放行 **22（SSH）** 和 **80（HTTP）**。**不要**放行 3306 和 3000，后端和数据库只在本机内部通信。

## 一、整体架构

```
浏览器 ──► http://公网IP/            ──► Nginx ──► 前端静态文件 dist/
           http://公网IP/api/...     ──► Nginx ──► 反代 127.0.0.1:3000（Node 后端）
           http://公网IP/public/...  ──► Nginx ──► 反代后端（上传文件/报告下载）
                                        Node 后端 ──► MySQL 127.0.0.1:3306
```

前端代码里的接口地址已全部改为**相对路径**（`/api/xxx`），所以：
- 本地开发：由 Vite 的 `server.proxy` 转发到本机 3000
- 线上：由 Nginx 转发到后端 3000

**换 IP、换域名都不需要再改代码。**

服务器上的目录规划：

```
/var/www/quality-inspection/
├── dist/                  # 前端打包产物
├── server/                # 后端代码
├── ecosystem.config.js    # pm2 配置
```

## 二、服务器初始化（只做一次）

### 1. 更新系统并安装基础工具

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl unzip git
```

### 2. 安装 Node.js 20 LTS

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v && npm -v        # 确认输出 v20.x
```

### 3. 安装 MySQL 8

```bash
sudo apt install -y mysql-server
sudo systemctl enable --now mysql
```

设置 root 密码（Ubuntu 下 root 默认用 auth_socket 登录，需要改成密码登录）：

```bash
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '这里换成你的强密码'; FLUSH PRIVILEGES;"
```

验证：

```bash
mysql -uroot -p -e "SELECT VERSION();"
```

### 4. 安装 Nginx

```bash
sudo apt install -y nginx
sudo systemctl enable --now nginx
```

### 5. 安装 pm2（进程守护）

```bash
sudo npm install -g pm2
```

### 6.（可选）PDF 转换所需的系统依赖

只有用到"PDF 转图片"相关功能才需要：

```bash
sudo apt install -y graphicsmagick ghostscript
```

## 三、上传代码

在你**本机**执行 `deploy\本地打包脚本.bat`，会在 `deploy\release\` 生成：

- `fe-dist.zip` —— 前端产物
- `server.zip` —— 后端代码（已排除 node_modules / .env / uploads）
- `nginx.conf`、`ecosystem.config.js`、`部署文档.md`

然后在**本机**用 scp 上传（把 `你的公网IP` 替换掉）：

```bash
scp deploy/release/fe-dist.zip deploy/release/server.zip \
    deploy/release/nginx.conf deploy/release/ecosystem.config.js \
    root@你的公网IP:/tmp/
```

> Windows 下没装 scp 的话，也可以直接用 FinalShell、WinSCP、腾讯云/阿里云控制台的文件上传。

回到**服务器**，创建目录并解压：

```bash
sudo mkdir -p /var/www/quality-inspection/{dist,server}
sudo chown -R $USER:$USER /var/www/quality-inspection

unzip -o /tmp/fe-dist.zip -d /var/www/quality-inspection/dist
unzip -o /tmp/server.zip   -d /var/www/quality-inspection/server
sudo mv /tmp/ecosystem.config.js /var/www/quality-inspection/
```

## 四、部署后端

```bash
cd /var/www/quality-inspection/server

# 安装依赖（跳过仅开发用的 nodemon）
npm install --omit=dev

# 配置环境变量
cp .env.example .env
nano .env
```

`.env` 里至少要改这几项：

```ini
PORT=3000
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你在第二步设置的MySQL密码
DB_NAME=quality_inspection

SESSION_SECRET=改成一串随机字符（可用 openssl rand -hex 32 生成）

# JWT 登录令牌密钥，同样改成随机长字符串（与 SESSION_SECRET 不同即可）
JWT_SECRET=改成另一串随机字符

# 跨域白名单（一般留空即可：前端经 Nginx 反代属于同源，不需要跨域）
# 仅当前端独立域名直连后端时才需要配置，例如：
# CORS_ORIGINS=https://你的前端域名.com

SMTP_SERVICE=qq
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的QQ邮箱
SMTP_PASS=你的QQ邮箱SMTP授权码

DEEPSEEK_API_KEY=你的DeepSeek Key
```

初始化数据库（**会自动建库、建表、创建默认管理员**）：

```bash
npm run init-db
```

> 注意：`init-db` 内部用的是 `sequelize.sync({ force: true })`，**会删表重建**。只在首次部署时执行，以后不要重复跑。

准备日志目录并启动：

```bash
sudo mkdir -p /var/log/quality-inspection
sudo chown -R $USER:$USER /var/log/quality-inspection

pm2 start ../ecosystem.config.js
pm2 save
pm2 startup          # 按提示复制粘贴执行它输出的那条命令，实现开机自启
```

查看状态与日志：

```bash
pm2 status
pm2 logs quality-inspection-server --lines 50
```

## 五、配置 Nginx

```bash
sudo cp /tmp/nginx.conf /etc/nginx/sites-available/quality-inspection
sudo ln -sf /etc/nginx/sites-available/quality-inspection /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default     # 移除默认站点，避免抢占 80

sudo nginx -t && sudo systemctl reload nginx
```

> 如果以后有了域名，把 `nginx.conf` 里的 `server_name _;` 改成你的域名再 reload 即可。

## 六、验收清单

浏览器打开 **`http://你的公网IP/`**，逐项确认：

| # | 检查项 | 预期 |
|---|---|---|
| 1 | 打开首页 | 显示登录页，不是 Nginx 欢迎页 / 502 |
| 2 | 登录 | `admin@example.com` / `admin123` 能进主页 |
| 3 | 改密码 | **立刻**把默认管理员密码改掉 |
| 4 | 上传合同 | 能选文件并上传成功 |
| 5 | 智能质检 | 触发一次质检，能返回结果（依赖 DeepSeek Key） |
| 6 | 结果导出 | 能下载生成的 docx 报告 |
| 7 | 刷新页面 | 在任意子页面按 F5 不出现 404 |
| 8 | 头像 | `/public/img/avatar-default.png` 能正常显示 |

对应的服务器侧排查命令：

```bash
pm2 logs quality-inspection-server   # 后端报错
sudo tail -f /var/log/nginx/error.log
```

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 打开是 Nginx 默认页 | `sites-enabled/default` 没删，或软链接没生效。执行 `sudo rm -f /etc/nginx/sites-enabled/default && sudo systemctl reload nginx` |
| 502 Bad Gateway | 后端没跑起来。`pm2 status`、`pm2 logs`，通常是 `.env` 里数据库密码不对 |
| 子页面刷新 404 | `nginx.conf` 的 `try_files $uri $uri/ /index.html;` 没生效，检查配置是否已 reload |
| 上传大文件失败 | 前端 `client_max_body_size 50m` 和后端 multer 限制要同时放宽 |
| 上传后文件/报告打不开 | `/public/` 的反向代理没配或没 reload |
| 数据库连不上 | 确认 `mysql -uroot -p` 能进；核对 `.env` 的 `DB_PASSWORD`；确认 3306 只监听本机即可 |
| 邮件验证码发不出 | `.env` 的 `SMTP_*` 未配置或授权码失效（QQ 邮箱需开启 SMTP 并获取授权码） |

### 已知遗留问题（改造前就存在，本次未改动）

前端 `QualityInspection.vue`、`QualityInspection1.vue` 中有 3 处调用了 **缺少 `/api` 前缀**的接口：

- `/get_quality_jpg_result`
- `/get_quality_list_result`
- `/upload_XImages`

后端这三个接口实际挂在 `/api` 下，所以这 3 处调用在改造前就是 404。如需修复，把前端里的路径改成 `/api/...` 即可。

## 八、日常运维

### 更新代码后重新发布

```bash
# 本机：重新执行 deploy\本地打包脚本.bat，然后 scp 上传新的 zip
# 服务器：
unzip -o /tmp/fe-dist.zip -d /var/www/quality-inspection/dist
unzip -o /tmp/server.zip   -d /var/www/quality-inspection/server
cd /var/www/quality-inspection/server && npm install --omit=dev
pm2 restart quality-inspection-server
```

> **重要**：上传的合同与生成的报告都在 `server/public/uploads/` 里，是业务数据。
> 重新上传 `server.zip` 时脚本已排除该目录，不会被覆盖；仍建议定期备份：
> `tar -czf ~/backup-$(date +%F).tar.gz -C /var/www/quality-inspection/server public/uploads`

### 常用命令

```bash
pm2 status                        # 进程状态
pm2 restart quality-inspection-server
pm2 logs quality-inspection-server
sudo systemctl reload nginx       # 改完 Nginx 配置后重载
sudo systemctl status mysql
free -h                           # 内存不足是 502 的常见原因
```

## 九、下一步：接域名 + HTTPS（可选）

1. 域名解析到服务器公网 IP（国内服务器需先完成 ICP 备案）
2. 把 `nginx.conf` 的 `server_name _;` 改成域名，reload
3. 申请证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名
```

certbot 会自动改好 Nginx 配置并配置自动续期。
